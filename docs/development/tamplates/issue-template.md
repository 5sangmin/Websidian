# Issue Template

## Title

한 줄로 이번 작업을 설명한다.

예:
- Vault 대표 문서 지정 API 추가
- HTML document rendering fallback 수정
- Compose 환경 변수 구조 정리

## Why

이 작업을 왜 지금 해야 하는지 적는다.

- 어떤 문제를 해결하려는가
- 어떤 기능을 가능하게 하려는가
- 왜 지금 필요한가

## Type

해당 작업의 성격을 표시한다.

- [ ] Feature
- [ ] Fix
- [ ] Refactor
- [ ] Docs
- [ ] Infra
- [ ] Research
- [ ] Chore

## Related docs

작업 전에 확인해야 할 문서를 적는다.

- `docs/...`
- `docs/...`

예:
- `docs/vision/scope-mvp.md`
- `docs/architecture/domain-model.md`
- `docs/backend/api-overview.md`

## Current context

현재 상태를 짧게 적는다.

- 지금 어떤 구조인가
- 어떤 점이 부족한가
- 이미 결정된 내용이 있는가

## Scope

이번 작업에서 실제로 할 범위를 적는다.

- 할 일 1
- 할 일 2
- 할 일 3

작업 범위는 가능한 작고 명확하게 유지한다.

## Out of scope

이번 작업에서 하지 않을 것을 적는다.

- 하지 않을 것 1
- 하지 않을 것 2

이 항목은 작업이 커지는 것을 막기 위해 반드시 적는다.

## Expected result

작업이 끝났을 때 무엇이 가능해져야 하는지 적는다.

- 사용자/개발자 입장에서 어떤 변화가 있는가
- 무엇을 확인하면 완료라고 볼 수 있는가

## Implementation notes

구현 전에 떠오른 메모를 적는다.

- 적용할 계층
- 조심할 포인트
- 관련 엔티티 / API / 화면 / 인프라 항목
- 나중에 문서로 남겨야 할 결정 사항

## Verification

최소 확인 항목을 적는다.

- [ ] 앱이 정상 기동한다
- [ ] 관련 기능이 의도대로 동작한다
- [ ] 관련 없는 부분이 깨지지 않았다
- [ ] 필요한 문서를 갱신했다

필요하면 아래를 추가한다.

- [ ] Backend API 확인
- [ ] Frontend 화면 확인
- [ ] DB 변경 확인
- [ ] MinIO/파일 처리 확인
- [ ] Compose 실행 확인

## Notes for next step

이번 작업 이후 바로 이어질 수 있는 다음 작업이나 남은 문제를 적는다.

- 다음 작업 후보
- 이번에 일부러 제외한 것
- 후속 문서화가 필요한 내용
